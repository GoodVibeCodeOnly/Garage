# 21 — Regression by hand

You've read a thousand regression tables. Today you build one from parts, so the numbers stop being magic: slope, intercept, residuals, R², the standard error, the confidence interval, then multiple regression with `numpy.linalg.lstsq`. No statsmodels — numpy and scipy only.

## The line

Simple OLS picks the line `y = a + b·x` that minimises the sum of squared residuals. The closed form:

```python
dx, dy = x - x.mean(), y - y.mean()
b = (dx * dy).sum() / (dx ** 2).sum()   # = cov(x, y) / var(x)
a = y.mean() - b * x.mean()             # the line passes through (x̄, ȳ)
```

Intuition: the slope is "how much x and y move together" divided by "how much x moves on its own". The n vs n−1 factors cancel, so you don't need `np.cov`.

## Residuals and R²

```python
resid = y - (a + b * x)
r2 = 1 - (resid**2).sum() / ((y - y.mean())**2).sum()
```

Residuals are what the model fails to explain. At the OLS solution they sum to zero (you get that for free from the intercept). R² is the share of y's variance the line accounts for. High R² ≠ causal, and low R² ≠ useless: a policy lever with a tight, real effect can still leave most variance unexplained.

## How sure are we about the slope?

```python
n = len(x)
s2 = (resid**2).sum() / (n - 2)          # residual variance; 2 params estimated
se = np.sqrt(s2 / (dx**2).sum())
t = stats.t.ppf(0.975, df=n - 2)
ci = (b - t*se, b + t*se)
```

The SE shrinks when residuals are small (less noise) and when x is spread out (more leverage). That second part is design advice: if you want to pin down an effect, sample across a wide range of the driver. The t distribution (not 1.96) matters when n is small — 40 elections is small.

## Multiple regression

Stack regressors into a matrix, prepend a column of ones for the intercept, solve:

```python
A = np.column_stack([np.ones(n), growth, unemp])
coef, *_ = np.linalg.lstsq(A, y, rcond=None)   # [intercept, b_growth, b_unemp]
```

`lstsq` returns several things (residuals, rank, singular values); `coef, *_ =` keeps the first. It's numerically safer than writing `inv(A.T @ A) @ A.T @ y`.

### Reading coefficients like an economist

`b_growth = 1.5` means: comparing two elections with the **same** unemployment change, the one with 1pp higher growth had ~1.5 points more incumbent vote, on average. "Holding others fixed" is the whole point of adding variables — it's how you partially strip out confounders you can measure.

What it does **not** mean:
- **Causation.** Coefficients are conditional associations. Omitted variables (war, scandal, a charismatic challenger) correlated with both growth and vote will bias the coefficient. Reverse causation is possible too (expected incumbent win → investment → growth).
- **Extrapolation is safe.** The line is fitted on the range you observed. Predicting a −10% growth year from data that never went below −3% is a guess with a straight edge.
- **Comparable magnitudes across variables.** Units differ. 1pp growth and 1pp unemployment are not the same-sized shock.

Think of it like reading a Paradox tooltip: "+15% tax income" is the modifier's effect *given everything else on the screen*. Change the other modifiers and the marginal effect stays — in a linear model, by assumption.

## Worked example
